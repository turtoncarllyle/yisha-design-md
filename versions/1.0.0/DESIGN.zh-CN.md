# YiSha 设计系统

## 1. 概述

YiSha 是一套紧凑、工作导向的后台管理界面，建立在 Bootstrap 3、jQuery、服务端 Razor 页面和少量自有 JavaScript API 之上。它的视觉识别由三个相互关联但用途不同的层次组成：

1. 蓝色顶栏和可折叠深色侧栏构成默认应用壳层。
2. 青绿色 `#1ab394` 是列表、表单、表格和工具页面中的主要操作色。
3. 登录页和运营看板采用更新的深绿色 `#0f8b72` 强调色、更强的字体层级和克制的 8px 表面。

必须保持这三层之间的边界。不要把整个壳层改成青绿色，也不要把登录页的大字号和深阴影搬到高密度 CRUD 页面。

本文档描述视觉结果、组件组合、交互状态和响应式行为，不替代 Bootstrap、插件、路由、权限或后端 API 文档。

## 2. 源码基线

本规范来自一份 .NET 10 MVC Web 前端快照，静态审计范围包括：

- 应用视图、共享布局和三个功能区域中的 50 个 Razor 文件。
- 完整壳层、列表页、白底表单和灰底表单共享布局。
- 自有 `style.css`、`skins.css`、`yisha.css`、`login.css` 及其生成后的 bundle。
- 自有页面、数据、初始化、表格、树表和 zTree JavaScript 适配器。
- 登录、看板、皮肤选择、账号、导入、树和详情页面的内联样式。
- `bundleconfig.json` 中的全部依赖项。

## 3. 设计原则

### 3.1 高密度、重操作

- 优先支持浏览、筛选、选择和重复操作。
- 正文保持 12px，大多数控件标签保持 12-14px。
- 相关筛选条件放在一个紧凑查询表面中，操作工具栏紧邻数据区。
- 记录管理优先使用表格和树，而不是卡片集合。

### 3.2 用结构建立层级

- 使用深色侧栏、蓝色顶栏、白色内容表面、边框和间距建立层级。
- 高饱和颜色只用于操作、选择、状态和少量图表序列。
- 页面背景保持安静，主要内容表面使用白色。

### 3.3 使用熟悉的页面模板

- 列表页使用共享 Index 布局、查询区、工具栏和 Bootstrap Table。
- 编辑与详情流程使用白底或灰底表单布局和 Bootstrap 水平表单。
- 跨页面工作流在壳层页签中打开，聚焦编辑在 Layer 对话框中打开。
- 权限与组织关系使用树或树表。

### 3.4 兼容性优先

- 复用既有类名、布局、插件适配器和 `ys.*` 辅助方法。
- 不要用外观相近但会破坏既有初始化或响应处理的组件替换原控件。
- 视觉现代化必须有明确上下文：登录页和看板是刻意设计的例外，不是全局重构模板。

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| 主要操作 | `#1ab394` | 主按钮、搜索、Select2 已选项、进度和焦点强调。 |

| 次级操作 | `#1c84c6` | 既有 `.btn-success`，用于次级正向操作或编辑。 |
| 信息 | `#23c6c8` | 既有 `.btn-info`、信息徽章和小型强调。 |
| 警告 | `#f8ac59` | 警告按钮、标签和需关注状态。 |
| 危险 | `#ed5565` | 删除、破坏性确认和错误状态。 |
| 正文 | `#676a6c` | 内容页面默认文字。 |
| 强文字 | `#333333` | 查询标签、表头和强调字段内容。 |
| 弱文字 | `#999999` | 次要元数据和非活动控件。 |
| 页面背景 | `#f3f3f4` | 默认灰色工作区。 |
| 表面 | `#ffffff` | 表单、表格、面板、下拉菜单和卡片。 |
| 边框 | `#e7eaec` | 表格、面板、页签和分隔线。 |

语义类名遵循源码，而不是现代 Bootstrap 的直觉：`.btn-success` 在这里是蓝色，最常见的肯定操作则使用青绿色 `.btn-primary`。既有页面必须保留这套映射。

### 4.2 默认壳层

- 顶栏：`#3c8dbc`。
- Logo 区和较深的顶栏悬停色：`#367fa9`。
- 深色侧栏：`#2f4050`。
- 侧栏活动和悬停行：`#293846`。
- 皮肤定义下的默认侧栏链接：`#b8c7ce`。
- 蓝色选中项：`#1890ff`；顶级活动导航使用 3px 壳层蓝左边框。
- 主工作区：`#f3f3f4`，内容表面为白色。

默认类组合是 `skin-blue theme-dark`。若存在持久化的 `Skin` Cookie，则应用其中保存的皮肤类和侧栏主题类。

### 4.3 可选壳层皮肤

| 皮肤 | 顶栏色对 | 浅色主题选中强调 |
| --- | --- | --- |
| 蓝 | `#367fa9` / `#3c8dbc` | 淡蓝表面上的 `#1890ff`。 |
| 绿 | `#008d4c` / `#00a65a` | 淡绿表面上的 `#52c41a`。 |
| 紫 | `#555299` / `#605ca8` | `#f9f0ff` 表面上的 `#722ed1`。 |
| 红 | `#dd4b39` / `#d73925` | 淡红表面上的红色强调。 |
| 黄 | `#f39c12` / `#e08e0b` | `#fffbe6` 表面上的 `#faad14`。 |

`theme-dark` 保持 `#2f4050` 侧栏；`theme-light` 使用 `#f9fafc`、接近 `#777` 的文字、轻微右侧阴影和随皮肤变化的活动状态。皮肤只改变壳层，不得重新映射内容区的操作语义。

### 4.4 登录与看板强调色

- 深绿：`#0f8b72`，用于焦点、图表线、指标图标和交互强调。
- 墨色：`#17202a` 或 `#17211d`，用于高对比标题和深色操作表面。
- 金色：`#f4bd3f` 或 `#f6c453`，用于小型品牌细节和时间强调。
- 辅助蓝：`#2f6fed`，用于登录页小标签或次级装饰细节。
- 看板画布：`#eef2f1`；看板边框：`#dce4e0`。

不要用这套颜色替换标准列表页操作色。它只服务于认证和分析概览界面。

## 5. 字体排印

### 5.1 默认字体栈与字号

- 默认字体栈：`"Microsoft YaHei", "open sans", "Helvetica Neue", Helvetica, Arial, sans-serif`。
- 基础字号 12px、字重 400、颜色 `#676a6c`。
- 10-11px 只用于紧凑计数、辅助标签或高密度元数据。
- 13-14px 用于导航、按钮、字段强调和普通面板标题。
- 16-18px 用于分区标题、对话框标题和紧凑看板标题。
- 24-30px 只用于页面级数字、错误状态或看板指标。

### 5.2 现代认证与看板字号

使用 front matter 中的系统优先字体栈。登录品牌字可达到 42px，登录主文案 30px，看板指标 28px。这些字号属于宽松的首屏界面，不得出现在工具栏、表格单元格或对话框中。

### 5.3 文本行为

- 字间距为 `0`，不要使用负字间距压缩文字。
- 表单标签使用常规字重，必填标记保持红色并紧邻标签。
- 只有稳定列宽或页签宽度确实需要时才截断文字，并通过 title 或可访问方式提供完整内容。
- 按钮文案要短且面向任务：搜索、重置、新增、编辑、删除、导出、保存、关闭。

## 6. 布局与间距

### 6.1 应用壳层

| 元素 | 尺寸 | 规则 |
| --- | --- | --- |
| 展开侧栏 | `200px` | 桌面端固定左侧导航。 |
| 折叠侧栏 | `50px` | `mini-navbar` 使用的图标轨道。 |
| 折叠菜单浮层起点 | `65px` | 二级浮层从图标轨道及其间距之后开始。 |
| 顶栏 | `50px` | 导航链接至少保持 50px 高度。 |
| 页签条 | `42px` | 内部页签控件高 40px。 |
| 页面偏移 | `200px` | 桌面端 `#page-wrapper` 左外边距。 |
| 壳层内容内边距 | `0 15px` | 应用于 `#page-wrapper`。 |
| 普通内容包裹 | `20px` | 标准 `.wrapper-content` 内边距。 |

壳层由深色固定侧栏、彩色顶栏、可横向滚动的页签条和每个活动页签对应的一个可见 `.admin-iframe` 组成。第一个首页页签必须常驻；相同 URL 已打开时复用现有页签，不创建重复页签。

### 6.2 列表页

- `.container-div`：上下 10px、左右 35px 内边距，占满可用高度。
- `.search-collapse` 和 `.select-table`：白色表面、6px 圆角、10px 上外边距、轻量 `1px 1px 3px rgba(0,0,0,.2)` 阴影。
- 筛选行项目：30px 高、上下 5px 外边距、右侧间隔 15px。
- 普通文本或下拉筛选框：280px × 30px。
- 日期范围两端：各 133px，中间使用紧凑分隔符。
- 表格单元格内边距 8px，行边框 `#e7eaec`，表头分隔线 `#cccccc`。
- 查询、工具栏、表格和分页应被理解为一个连续工作区。

### 6.3 表单

- 标准对话框使用 Bootstrap 12 列栅格和 `.form-horizontal`。
- 常见标签/内容比例是 `col-sm-3` + `col-sm-8` 或 `col-sm-2` + `col-sm-10`。
- 标准 Bootstrap 表单控件约 34px 高，内边距 6px × 12px。
- 面板内边距保持 15-20px，事务型表单不要产生大片无意义留白。
- 保存和关闭放在对话框底部或宿主 Layer 按钮区，不放在无关的浮动卡片里。

### 6.4 看板与登录

- 看板外层内边距 18px，网格间距 12-14px。
- 看板卡片使用 8px 圆角和 16-18px 内边距。
- 登录卡片宽 386px、内边距 30px、圆角 8px。
- 登录控件和主按钮高 48px。
- 这些布局可以宽松，但普通笔记本首屏仍应露出下一段有意义的内容。

## 7. 阴影与形状

### 7.1 圆角层级

- 1px：传统内容层中的标准表单控件。
- 2-3px：按钮、下拉菜单、加载器、紧凑面板和壳层细节。
- 4px：筛选控件、复选框轮廓和已有定义的普通 Bootstrap 控件。
- 6px：列表查询与表格表面。
- 8px：仅用于登录和看板卡片。
- 50%：头像、圆形状态或圆形图标控件。

不要把全部组件统一成 8px。圆角用于区分高密度 CRUD 表面和较新的首屏表面。

### 7.2 阴影层级

- 扁平：表单控件、面板、进度和大多数内容组件使用 `box-shadow: none`。
- 细边卡片：小型 `.box` 使用 `0 1px 1px rgba(0,0,0,.1)`。
- 列表表面：`1px 1px 3px rgba(0,0,0,.2)`。
- 下拉菜单：轻量 `0 0 3px rgba(86,96,117,.3)` 或等价阴影。
- 看板：`0 12px 28px rgba(23,33,29,.07)`。
- 登录：仅认证卡片使用更强的 `0 28px 70px rgba(23,32,42,.22)`。

避免卡片层层嵌套和重复重阴影。通常一个表面边界已经足够。

## 8. 组件

### 8.1 顶栏、侧栏与账号菜单

- 导航标签前使用 Font Awesome 图标。
- 顶级侧栏项可以包含二级和三级列表。
- 页签激活时，其导航祖先保持展开和选中状态。
- 折叠按钮使用 bars 图标，极窄屏幕显示关闭入口。
- 账号菜单以紧凑下拉形式包含头像、身份、个人资料、密码、皮肤和退出操作。
- 保持 50px 顶栏节奏，不要在其上方再添加第二条工具栏。

### 8.2 页签工作区

- 页签条高 42px，内部控件高 40px。
- 提供左移、右移、刷新、关闭当前、关闭其他和全部关闭行为。
- 活动页签有清楚差异，并同步回侧栏选中项。
- 页签关闭图标属于次级操作，悬停时变为危险色。
- iframe 填满剩余工作区，并在完成加载前显示加载状态。

### 8.3 查询与工具栏

- 筛选条件放在 `.search-collapse` 中，使用带标签的输入框、下拉框和日期范围。
- 搜索使用主要青绿色操作，重置使用中性或白色样式。
- 工具栏紧邻表格上方，使用带图标的小按钮。
- 新增使用主操作或正向语义；编辑要求正好选中一行；删除要求至少选中一行。
- 禁用操作既要显示禁用状态，也必须拒绝交互，不能只改颜色。

### 8.4 按钮

| 类型 | 类 | 视觉角色 |
| --- | --- | --- |
| 主要 | `.btn-primary` | 青绿色新增、保存、确认或搜索。 |
| 次级正向 | `.btn-success` | 既有页面中的蓝色编辑、启用或次级操作。 |
| 信息 | `.btn-info` | 青蓝色信息或查看操作。 |
| 警告 | `.btn-warning` | 琥珀色重置、暂停或谨慎操作。 |
| 危险 | `.btn-danger` | 红色删除、撤销授权或破坏性操作。 |
| 中性 | `.btn-white` / 默认 | 关闭、取消或低强调工具操作。 |

工具栏使用 `.btn-sm`，高密度表格操作列使用 `.btn-xs`。所有纯图标按钮必须有可访问名称或工具提示。

### 8.5 表单与校验

- 使用 `.form-control`、`.form-group`、`.control-label` 和 Bootstrap 栅格列。
- 必填字段在标签旁显示红色标记。
- 校验消息使用 12px 红色文字，放在关联控件附近且不能遮挡已输入内容。
- 错误控件使用淡红背景或红色边框；成功状态不能只依赖颜色表达。
- Select2 只用于可搜索或多值选择，已选标签使用主要青绿色。
- 共享表单布局下的复选框和单选框通过 iCheck 蓝色皮肤初始化。
- ID 必须稳定，因为初始化和校验会从 ID 派生行为。

### 8.6 表格与分页

- 可排序、可分页记录列表使用 Bootstrap Table。
- 表头使用较强文字和清晰底边，数据行保持白色或轻量斑马纹。
- 状态、选择、日期和操作等窄列在有助于浏览时可居中。
- 保留服务端分页和本地适配器预期的响应契约。
- 分页使用白色、上下 4px 左右 10px 的控件；活动页为浅灰，不使用大面积胶囊填充。
- 紧凑状态使用徽章或标签，同时提供脱离颜色仍有意义的文字。

### 8.7 树与树表

- 菜单、部门、区域和权限选择使用 zTree。
- 需要同时展示层级和记录列时使用 Bootstrap TreeTable。
- 展开/折叠控件与第一列有意义内容对齐。
- 只有层级足够大时才提供全部展开/全部折叠。
- 新实现必须支持键盘选择，即使旧适配器没有完整的 ARIA tree 模型。

### 8.8 面板、Box 与看板指标

- 有边界的内容工具使用 `.ibox` / `.ibox-title` / `.ibox-content` 或 `.box`。
- Ibox 标题通常为 14px，工具控件位于右侧。
- 可折叠、可关闭面板保留可见工具图标和稳定内容尺寸。
- 看板指标可使用 8px 卡片、34px 图标块、28px 数值和简短 12px 辅助文字。
- 不要在卡片中再嵌套卡片，也不要把每个页面分区都做成浮动卡片。

### 8.9 对话框、反馈与加载

- 聚焦 CRUD 表单使用 `ys.openDialog`，已有 HTML 内容使用 `ys.openDialogContent`。
- 破坏性操作前使用 `ys.confirm`。
- 简短结果使用 `ys.msgSuccess`、`ys.msgWarning` 和 `ys.msgError`。
- 只有必须确认时才使用 alert 变体。
- 异步或 iframe 工作期间使用 `ys.showLoading` / `ys.closeLoading`。
- 成功消息应作为礼貌状态更新，破坏性失败应作为强提示警报。

### 8.10 日期、上传、头像与图表

- 日期字段和相互约束的起止日期范围使用 Laydate。
- 文件导入使用 File Input，并显示文件名、进度、成功和失败状态。
- 头像裁剪使用 Cropbox，保留预览、裁剪边界以及明确的保存/取消操作。
- 只有图表比表格更适合表达比较或趋势时才使用 ECharts。
- 看板图表颜色以深绿开始，可增加蓝、琥珀、红和弱绿色序列。

## 9. 交互模式

### 9.1 自有辅助方法契约

在当前应用中实现页面时优先使用既有辅助方法：

- `ys.ajax`：应用请求和标准成功/错误响应处理。
- `ys.ajaxUploadFile`：上传。
- `ys.openDialog`、`ys.openDialogContent`、`ys.closeDialog`：弹层工作流。
- `ys.confirm`：破坏性确认。
- `ys.msgSuccess`、`ys.msgWarning`、`ys.msgError`：短时反馈。
- `ys.alertSuccess`、`ys.alertWarning`、`ys.alertError`：阻塞式反馈。
- `ys.showLoading`、`ys.closeLoading`：等待状态。
- `ys.getIds`、`ys.checkRowEdit`、`ys.checkRowDelete`：依赖选择状态的工具栏操作。
- `ys.exportExcel`：既有导出流程。
- `ys.formatDate`、`ys.isNullOrEmpty` 及相关工具：保持页面约定。

不要在既有页面中另建一套 fetch、Modal 或 Toast 体系。

### 9.2 初始化

- 共享初始化负责 iCheck、Select2、日期范围、校验 name、树搜索和工具栏权限。
- 表格选择至少一行时启用删除，且只有正好一行时启用编辑。
- 壳层导航初始化 MetisMenu 和 4px SlimScroll 滚动轨道。
- 皮肤选择器把 `皮肤名|主题名` 持久化到 `Skin` Cookie。
- 每个异步操作都要展示等待、成功、空数据和错误状态。

### 9.3 动效

- 边框、简单变换、菜单和状态变化使用 150-300ms 过渡。
- 侧栏折叠时的内容淡入可接近既有的 500ms 行为。
- 动效必须解释状态变化，避免装饰性弹跳、视差或持续动画。
- 新 CSS 尊重 reduced-motion 偏好。

## 10. 响应式行为

### 10.1 壳层与列表页

- 低于 769px 时，壳层进入 `mini-navbar` 行为。
- 768px 及以下时，固定侧栏默认隐藏，直到用户明确切换。
- 767px 及以下时，下拉菜单和账号头像细节为窄屏收紧。
- 350px 及以下时，折叠侧栏宽度变为 0，并显示关闭入口。
- 源码在低于 768px 时隐藏列表查询面板；新页面应提供明确的筛选展开按钮，不能让筛选功能不可达。
- Bootstrap Table 移动扩展可以收起低优先级列，但必须保留主要标识和操作路径。

### 10.2 登录页

- 880px 及以下使用不超过 430px 的单列壳层，并隐藏装饰性操作格。
- 420px 及以下把记住账号和默认账号内容纵向排列。
- 表单卡片必须留在视口内，横向至少保留 14px 呼吸空间。

### 10.3 看板

- 1180px 以上时，指标使用六个等宽列。
- 1180px 及以下时，指标改为三列。
- 820px 及以下时，页头、指标和分析面板改为单列堆叠。
- 图表随窗口调整尺寸，并保持明确稳定的高度。

### 10.4 传统断点

源码还包含 Bootstrap 时代的 992px、1170px 和 1200px 栅格及工具可见性边界。使用最接近的既有页面模式，不要用随视口缩放的字体，也不要为现有栅格已经能解决的问题新增断点。

## 11. 无障碍

源码是视觉基线，不代表必须复制其中的无障碍缺口。

- 保留浏览器缩放，不复制禁用用户缩放的 viewport 设置。
- 命令使用真实 `<button>`，导航使用真实链接。
- 纯图标控件提供可访问名称和清晰焦点状态。
- 可折叠菜单与面板补充 `aria-expanded` 和 `aria-controls`。
- 每个工作区 iframe 都提供有意义的 `title`。
- 标签和校验消息必须与表单控件建立关联。
- 对话框打开时把焦点移入，关闭时归还触发元素。
- 普通成功和进度消息使用 `role="status"` / `aria-live="polite"`。
- 只有紧急错误使用 `role="alert"` 或 assertive live region。
- 状态不能只用颜色表达，还应包含文字或带可访问名称的图标。
- 页签、树、下拉菜单、分页和表格操作必须支持键盘访问。
- 第三方默认能力只是起点，缺失语义要在应用层补足。

## 12. Do / Don't

### Do

- 从共享列表、白底表单、灰底表单或壳层布局开始。
- 保持 CRUD 页面紧凑并以表格为中心。
- 使用源码提取的准确色板和语义类映射。
- 除非用户选择了其他皮肤，否则保留默认蓝色/深色壳层。
- 复用既有插件适配器和 `ys.*` 辅助方法。
- 提供加载、空数据、成功、校验、无权限和失败状态。
- 把现代深绿风格限定在登录和分析概览界面。
- 在不改变视觉语言的前提下改进语义、焦点和键盘操作。

### Don't

- 不要把记录列表改成营销卡片或装饰性 Bento 布局。
- 不要在工具栏、对话框、表格或侧栏中使用超大标题。
- 不要给标准 CRUD 页面增加渐变、玻璃效果、大胶囊控件或重阴影。
- 不要把所有语义操作都改成青绿色，也不要假设 Bootstrap 类名具有现代语义。
- 不要在同一页面混用多套图标库。
- 不要卡片套卡片，也不要让每个页面分区都漂浮在画布之上。
- 不要在 iframe 页面内重复壳层顶栏、侧栏或页签管理器。
- 不要绕过具备权限感知能力的工具栏初始化。
- 不要复制不可访问的锚点、禁用缩放、缺失标签或无反馈异步失败。

## 14. 已知缺口与迭代清单

### 已知缺口

- 源码使用字面 CSS 值，没有集中式自定义属性令牌系统；本文令牌是语义别名，不是运行时变量。
- 紧凑壳层/内容层与较新的登录/看板层使用不同字号和阴影尺度，必须明确保持边界。
- 多个插件是传统 jQuery 组件，页面依赖其事件和数据结构，仅替换外观并不安全。
- iframe 页签工作区的原生语义有限，新实现需要补充 title、焦点管理和键盘行为。
- 树控件默认没有完整 ARIA tree 或 roving-tabindex 模型。
- 传统 CSS 在移动端隐藏列表筛选，新实现应提供明确的筛选展开入口。
- 本版本记录一份已审计快照；用于明显不同的 YiSha 前端前必须重新审计。
